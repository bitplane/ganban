# merge-tree exit code ignored, crash instead of None

`writer.py:133` — _merge_trees never checks git merge-tree's return code. On hard failure (exit > 1: pruned object, unsupported git version) stdout is empty, tree_hash becomes '', and try_auto_merge runs `git commit-tree ""` which raises CalledProcessError.

Callers are documented to receive None on failure: `ganban sync` dies with a raw traceback instead of reporting the conflict, and the daemon loop logs a crash every interval.
