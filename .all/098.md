# duplicate column order prefixes lose a column

`loader.py:233` — columns are keyed by order prefix in `columns_ln[order] = col`, so `2.doing` and `2.done` (easily produced when two replicas each create a column with the same next order and a file-level merge combines the directories) silently overwrite each other in the ListNode.

The next save writes only board.columns, permanently deleting the losing column's directory and card links — cards fall out of every column and get flagged archived, no warning.

Fix must handle collisions in code (e.g. re-key/renumber on load) — no format change.
