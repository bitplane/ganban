# code review fixes

Verified findings from the 2026-08-07 high-effort code review. Constraint: no changes to the on-branch data format — all fixes must be code-only.

- [ ] `writer.py:290` save_board force-moves the branch ref past commits from other processes (no compare-and-swap, divergence check runs after save) — silently orphans CLI commits made while the TUI is open
- [ ] `sync.py:95` multi-remote merge loop reuses the stale in-memory tree, so merging remote B discards remote A's just-merged changes (cli/sync.py reloads per-remote; TUI path doesn't)
- [ ] `loader.py:233` duplicate column order prefixes (e.g. `2.doing` + `2.done`) silently overwrite in the ListNode; next save deletes the losing column's directory
- [ ] `sync.py:114` nothing watches board `columns` membership, so columns added/archived by a remote merge never mount/unmount in the TUI until restart
- [ ] `writer.py:136` conflict-path regex grabs the last token of CONFLICT lines — mis-parses modify/delete messages and paths with spaces, so conflict resolution silently no-ops
- [ ] `loader.py:84` preamble text above a card's H1 gets retitled to the card id on round-trip, demoting the real title to an H2 and committing the corruption
- [ ] `loader.py:266` links watchers only registered on load-time columns; columns created at runtime never trigger archived/blocked recompute
- [ ] `writer.py:133` _merge_trees ignores git merge-tree's exit code; hard failure yields empty tree hash and a commit-tree crash instead of returning None
- [ ] `sync.py:65` background save via asyncio.to_thread iterates Node/ListNode structures the main thread mutates concurrently — no lock or snapshot (plausible race, silent data loss window)
- [ ] `node.py:119` Node.update iterates set(other.keys()) so merged-in keys land in nondeterministic order — noisy YAML front-matter diffs between replicas
