# Preserve live edits made after the sync snapshot when merging

src/ganban/sync.py:90 snapshots the live board; src/ganban/sync.py:46-51 merges that snapshot and replaces live state through apply_reload at line 32.

Reproduced with a real temporary Git repo: load the TUI board, save an external new card, then attach a sync.status watcher that edits card 1 when status becomes load (after the snapshot). Run run_sync_cycle. The live edit is replaced by the original Description. text. No mocks were used.

Expected: preserve edits made after the snapshot while incorporating external changes. Add a deterministic regression test covering this interleaving; ensure the next save retains both changes.

## Resolution

Fixed in code commit b5474f6. Sync merges use worker snapshots and defer applying the reload when live board contents have changed since the save snapshot. The live commit base stays intact so the next cycle saves the edits and merges external changes.

Verified the text-edit regression fails before the fix. Added coverage for metadata lists, board/column changes, new cards, and multiple remotes. All 13 sync tests and the full 729-test suite pass; commit hooks pass.
