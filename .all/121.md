# section-level merging

Conflict resolution is most-recent-commit-wins at file granularity: when two
replicas edit the same card, one side's edits are discarded wholesale. Cards
are structured markdown (sections, comments, task lines), so a semantic merge
could combine both sides instead.

Sketch:
- keep git merge-tree for the tree-level merge (clean cases stay as-is)
- for content-conflicted card files, parse both sides + base with
  `parser.parse_sections` and merge per section; append-only sections
  (Comments) can union, task lists can merge per line
- fall back to most-recent-wins only for truly overlapping edits

This unlocks card 26 (conflict on new card) and makes concurrent multi-user
editing genuinely safe.
