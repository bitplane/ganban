# TUI multi-remote merge drops earlier remote's changes

`sync.py:95` — the per-remote merge loop reuses the stale in-memory board tree between merges. After merging remote A, the board Node isn't reloaded before merging remote B, so try_auto_merge rebuilds our_tree from pre-A state and fast-forwards straight to B's state without A's changes.

Cards and edits pulled from remote A silently vanish every sync cycle when two remotes both have new commits. cli/sync.py avoids this by reloading inside the loop; the TUI path does not.
