# Node.update inserts new keys in nondeterministic order

`node.py:119` — Node.update iterates `set(other.keys())`, so keys added during update land in hash-random order. After a sync merge, card meta gained remotely (done, due, labels) is inserted in random order and yaml.dump(sort_keys=False) serializes front-matter that way.

Result: spurious front-matter diffs that differ between replicas — noisy commits and avoidable merge conflicts on the same files. Fix: iterate in other's insertion order.
