# save can orphan concurrent commits

`writer.py:290` — save_board unconditionally moves refs/heads/ganban to the new commit (parent = stale board.commit) with no compare-and-swap, and the only divergence guard (check_for_merge) runs AFTER save in the sync cycle and never before ctrl+s or quit.

With the TUI open, a `ganban card add` from the shell commits Y and advances the tip; the next TUI save commit-trees from stale state and update-refs past Y. board.commit then equals the tip so check_for_merge returns None — the CLI-created card vanishes, recoverable only via reflog.

Fix idea: `git update-ref` with the expected old value (CAS), and merge-then-save instead of save-then-check. Code-only, no format change.
