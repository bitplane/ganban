# conflict-path regex mis-parses CONFLICT lines

`writer.py:136` — the regex captures only the last whitespace-delimited token of each CONFLICT line, so modify/delete messages ("... left in tree.") capture `tree.` instead of the path, and any path containing spaces mis-parses.

_resolve_conflicts then ls-trees nothing and no-ops: the most-recent-commit-wins policy is silently skipped. An archived column can resurrect, or conflict markers get committed inside board files.

Verifier reproduced this against real `git merge-tree --write-tree` output. Better fix: use `-z` / structured output instead of regexing the human-readable message.
